# 上线检查清单

**逐条走，不许跳。勾不动的写明原因，不要空着。**
每次发版复制一份，勾完留存 —— 这些记录是「开发周期较长」那条痛点的 D 维度原料。

---

## 一、封版

- [ ] 本次要发的内容已冻结，列了清单
- [ ] 封版时间已通知到全组和需求方
- [ ] 之后提的新需求已明确答复「进下一版」
- [ ] 有变更的，已经要到「延期 X 天」或「砍掉 Y 功能」的确认

## 二、代码

- [ ] 主干上所有待发的改动已合并，没有游离分支
- [ ] 本地跑过一遍完整流程，不是只看编译通过
- [ ] 没有遗留的调试代码、`console.log`、临时开关
- [ ] 密钥、token、内网地址没有写进代码或配置文件
- [ ] 依赖没有引入新版本（或已确认新版本没问题）

## 三、数据

- [ ] 有数据库改动的，迁移脚本已准备好并且**在预发环境跑通过**
- [ ] 迁移脚本是**可重复执行**的（跑两次不会坏）
- [ ] 迁移前的数据已备份，备份**验证过能恢复**
- [ ] 有不可逆的操作（删列、删表、改类型）已经单独标出来并确认过

## 四、配置与环境

- [ ] 生产环境需要的变量都配了
- [ ] 静态资源路径、域名、回调地址指向生产而非测试
- [ ] 缓存/CDN 的刷新策略已确认
- [ ] 定时任务、队列、第三方回调的地址已切到生产

## 五、验证

- [ ] 主流程走通一遍（不是抽查，是完整走一遍）
- [ ] 关键路径在手机和桌面上各看过一次
- [ ] 控制台没有报错
- [ ] 加载性能没有明显退化
- [ ] 无 JS / 降级场景下页面仍然可用

## 六、通知

- [ ] 发版说明已写好并发出
- [ ] 需求方知道什么时候可以验收
- [ ] 有停机时间的，已提前通知
