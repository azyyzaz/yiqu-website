# ui-style —— 让界面不带 AI 味

「UI 风格贫瘠、不好看」是本组 PFDIS 评分里总分最高的一条（400 分，P=5 最痛）。
它的最低维是 **D 数据 = 2 / I 可描述 = 2** —— 不是不痛，是**资料和标准都不在手上**。

这个 skill 就是那两份资料。先补数据，再谈 AI。

## 铁律

**动任何界面之前，先读完下面三份，再写第一行 CSS。**

| 文件 | 作用 |
|---|---|
| `references/anti-patterns.md` | 「不要什么」清单 —— 违反任何一条即不合格 |
| `references/tokens.md` | 设计变量 —— 颜色、字号、间距、圆角只能从这里取 |
| `references/style-library.md` | 风格参考库 —— 定方向时看这里 |

三份都在本 skill 目录下。没读完就动手，产出的一定要返工。

## 工作流

1. **定方向** —— 从 `style-library.md` 挑 1~2 个参考，说清这次学它的什么（配色？留白？字重对比？）
2. **取变量** —— 颜色、间距、圆角、字号一律走 `tokens.md` 里的变量，**不写裸值**
3. **写界面**
4. **过清单** —— 逐条对照 `anti-patterns.md` 自检，并把自检结果明确说出来

## 交付前必须自问

- 把 logo 和所有文案遮住只看版式，像不像某个现成模板？
- 有哪一处是「因为框架默认这样」就留下来的？
- 间距是不是全篇一个值？有没有疏密节奏？
- 把所有图标和 emoji 去掉，版面还立得住吗？

## 该停下来问的时候

- `tokens.md` 里没有你要的变量 —— 先问要不要加，**不要自己造一个近似的**
- 需要新增一类组件 —— 先确认它是不是已有模式的变体
- 用户说「好看」但说不出哪里好看 —— 这正是 I=2 的症状，追问到能写成文字为止

## 这个 skill 的边界

它管**风格**，不管功能和对错。别用它去改交互逻辑、性能或无障碍问题 —— 那些各有各的规矩。
