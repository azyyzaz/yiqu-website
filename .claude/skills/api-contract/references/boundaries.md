# 边界情况十条

**写契约之前逐条过。不适用的，明确写「不适用，因为…」** ——
不写的，联调那天会由对接方替你问出来。

正常路径两边都会测，异常路径两边都假设对方会处理。这十条按"最容易吵起来"排序。

---

## 1. 结果为空

**问：** 查不到数据时，返回空数组、空对象，还是 404？

**为什么必吵：** 前端习惯 `if (list.length)`，后端习惯「查不到就是 404」。
两种都合理，凑一起就是线上白屏。

| 写法 A | 写法 B |
|---|---|
| 200 `{"items":[]}` | 404 `{"error":"NOT_FOUND"}` |
| 列表类接口用这个 | 单个资源用这个 |

**规则：列表返回空数组，单个资源返回 404。** 选哪个都行，写下来。

---

## 2. 条数上限与分页

**问：** 最多返回多少条？超了怎么办 —— 报错、截断，还是异步？

**为什么必吵：** 不写上上限，测试环境 10 条数据一切正常，
生产环境 5 万条直接把服务打挂。

```
· 默认 20 条，上限 100 条，超了返回 400
· 或不分页，但硬上限 5000 条，超了 400 {"error":"TOO_MANY_ROWS"}
· 或转异步，返回 task_id，前端轮询
```

**三条路都行，写清楚走哪条。** 最怕的是没写，于是各人按自己的量级假设。

---

## 3. 参数非法

**问：** 类型错、超范围、格式对不上，各自返回什么？

**为什么必吵：** 一边返回 400，一边返回 200 + `{"ok":false}`。
前端只处理了一种，另一种直接进了 success 分支。

```
400  {"error":"INVALID_RANGE", "field":"from", "message":"from 不能晚于 to"}
```

**带上 `field` 和 `message`。** 只给个错误码，前端只能显示"操作失败"，
排查还是得问后端。

---

## 4. 权限不足

**问：** 未登录、已登录但没权限、被禁用 —— 三种一样吗？

**为什么必吵：** 前端要根据状态码决定"跳登录页"还是"提示无权限"。
都返回 401 的话，没权限的用户会被反复弹去登录页。

```
401  未登录 / 登录过期     → 前端跳登录页
403  已登录但无权限         → 前端提示，不跳转
```

---

## 5. 重复提交与幂等

**问：** 用户连点两次、网络重试、消息重投 —— 会不会产生两条记录？

**为什么必吵：** 开发环境手速慢，永远复现不出来；上线第一天就有人连点。

```
· 前端按钮点击后禁用（不够，重试仍然会重发）
· 服务端按 <业务唯一键> 去重，重复请求返回第一次的结果
· 或要求带 Idempotency-Key 请求头
```

**写「幂等」两个字不算写清楚**，要写按什么去重。

---

## 6. 超时与重试

**问：** 多久算超时？客户端重试几次？重试会不会有副作用？

**为什么必吵：** 一边超时 30 秒，一边 5 秒就断开重试，于是同一单下了三次。

```
· 客户端超时 10s，重试 2 次，退避 1s/3s
· 只有 GET 自动重试，写操作不自动重试
```

**写操作不自动重试** —— 这条能挡掉一大类事故。

---

## 7. 并发

**问：** 同一条数据被两个人同时改，后写的覆盖先写的，还是报冲突？

**为什么必吵：** 乐观锁、悲观锁、最后写入胜出，三种方案前端处理完全不同。

```
· 最后写入胜出（简单，会丢更新）
· 带 version 字段，不匹配返回 409 {"error":"CONFLICT"}
```

选简单的可以，**但要写明选了哪个**，别让它成为默认行为。

---

## 8. 时间与时区

**问：** 传的是 UTC 还是本地时间？格式是什么？带不带时区偏移？

**为什么必吵：** 差 8 小时，报表数据对不上，而且只在跨天时暴露，
测试环境往往测不出来。

```
· 一律 UTC，ISO 8601 带 Z：2026-09-24T06:00:00Z
· 前端负责转本地时区展示
· 只到日期的地方（如报表范围）明确按 <哪个时区> 的零点算
```

**最后一行的坑最深**：`2026-09-01` 是 UTC 的 9 月 1 日还是东八区的？

---

## 9. 特殊字符与编码

**问：** 用户输入里有引号、换行、emoji、中文，导出/存储会怎样？

**为什么必吵：** 测试数据都是"张三""测试1"，
真实数据里第一条就是 `"李"某"` 或者一个 emoji。

```
· 编码 UTF-8
· 导出 CSV 时：字段内含逗号/引号/换行 → 用双引号包裹，内部引号加倍
· CSV 开头加 BOM，否则 Excel 打开中文乱码    ← 最常被漏
```

**「Excel 打开乱码」几乎是导出功能的标配 bug**，写下来能省一次返工。

---

## 10. 部分成功

**问：** 批量操作里第 3 条失败了，前 2 条回滚吗？返回什么？

**为什么必吵：** 事务回滚、跳过继续、部分提交 —— 三种语义，前端处理完全不同。

```
· 全部成功或全部失败 → 200 / 400，不留中间态
· 或逐条处理 → 207 风格：200 {"succeeded":[1,2],"failed":[{"id":3,"reason":"..."}]}
```

**这条排最后不是最不重要，是最容易整条忘掉。**
一旦接口是批量的，就要问它。

---

能，就可以去过 G2 了。不能，缺的那一条就是联调那天要吵的。
